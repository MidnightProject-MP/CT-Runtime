# CT-Runtime State

CT-Runtime is an experimental capability-first distributed execution runtime. The
filesystem implementation remains the local/test adapter; production experiments
use durable coordination and evidence adapters plus provider-neutral execution
federation. It carries no production reliability claim.

State is caller-owned and lives under the selected `--store`: manifests, leases, lock files, schedules, bounded raw evidence, result handoffs, events, telemetry, and the Observer bridge directory. Files are retained indefinitely unless the external supervisor applies its own reviewed retention policy.

The external supervisor supplies model, agent, bootstrap task, cwd, executable, timeout/retry bounds, and Observer path. Task Scheduler may invoke the one-shot `scheduler` command and periodically invoke `recover` and `observe-pending`.

The configured current prototype binding is Northflank for `disposable_compute` and `scheduler`, using the existing immutable CT-Runtime image, Neon durable state, and Backblaze B2 evidence store. Northflank API discovery identified the existing `CT-Runtime` project as `ct-runtime`; it currently has no jobs. Live job/secret permission, project secret-group, image, runtime credential, and model-secret authorization plus fresh-container proof are pending; this is not a verified deployment claim.

The production `evidence_store:s3` binding actively uses Backblaze B2 bucket `ct-runtime-evidence` in `us-east-005` with a bucket-scoped read/write application key. Real-provider S3 conformance, production doctor, reconstruction, and the regression suite passed on 2026-08-30. Reconstruction had zero canonical evidence references, so cross-provider continuity for existing evidence objects remains unexercised. The standard adapter prefers atomic conditional writes and bounded readback verification; B2 rejects the conditional header, so only its rechecked GET/unconditional PUT/GET fallback is non-atomic against a competing writer.

Residual limitations: an external supervisor is required; an Observer semantic provider is not configured by default; OpenCode fields are unavailable unless an adapter supplies them; unsupported topology, task, and orchestration fields are not claimed to survive Foundry projection; and Observer immutable conflict detection remains external.

Duration alone never requests `general_compute`; that remains unavailable and would require an exact capability gap reason. GAS is remote/provider metadata to Node, and Google authorization, deployment-owned storage, Script Properties, workflow allowlisting, and trigger setup remain human trust gates.

## First Autonomous Objective Loop — active milestone, not achieved

2026-09-08 local bounded slice: feedback objectives, including legacy verification checkpoints, are separated from the acknowledgement diagnostic. Until a qualified objective executor exists, nonterminal objective work persists `waiting` with named condition `execution_capacity`, a useful sheet response, and a bounded factual Chronicle entry. It does not invoke the acknowledgement model, verify an artifact as objective completion, or start a physical execution. Safety recovery consults each order's current revision instead of replaying historical lifecycles and retires due objective wakes without repeated execution attempts. Terminal orders are not reopened; legacy completed feedback projects as **Needs review**, not Verified. Explicit acknowledgement/`gas-a-b` diagnostics remain separate; federation reports transport checkpoint facts, not objective success.

The milestone has three slices:

1. **Truthful state:** this local semantic guard is implemented and tested. Still required: one current row per entity, a separate factual journal, bounded wake retry/cursor rules, and an isolated, reconciled migration proof **before any live cutover**. The existing append-revision Sheets layout is unchanged; this is not completion of the state migration.
2. **Real Celestan turn:** an explicitly bound host must run the actual objective and persist `continue` / `waiting` / `done`, completion evidence, the current continuation cursor, and a fence guard. Celestan owns judgment and `requested_next_wake`; runtime mechanics and transport receipts cannot manufacture success. Not implemented here.
3. **Same-objective conversation events:** human messages, replies, questions, and updates must append to the same objective identity instead of admitting a new work order for each revision. Not implemented here.
