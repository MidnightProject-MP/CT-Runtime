# CT-Runtime V2

V2 separates disposable execution from authoritative state. PostgreSQL owns deployments, work orders, executions, attempts, topology, leases, schedules, events, telemetry, evidence indexes, and Observer lifecycle. S3-compatible storage owns bounded raw evidence. Git owns source and deliberately curated authored knowledge only.

Observer persistence hashes canonical immutable digest content while excluding only generated `observedAt`. Digest insertion, semantic-task indexing, lifecycle transitions, semantic sidecars, and execution Observer timestamps are reconciled transactionally. Authoritative model envelopes and host samples use separate tables and APIs. Export always uses Foundry's validated joined projection.

`FilesystemStore` remains the local compatibility adapter. `CT_RUNTIME_MODE=production` selects PostgreSQL plus S3 and fails closed; it never falls back to local files. `migrate --database-url URL` is an explicit migration-role command. Normal jobs do not migrate.

## Retention

Use `ephemeral`, `operational`, `audit`, `observer-ledger`, `chronicle`, and `quarantine` classes. Raw operational evidence may expire only after its digest, hash, reference, and required provenance are durable. Digest, semantic, lifecycle, policy, consolidation, and Chronicle records are append-only; corrections are new records.

## Deployment

Cloud Run Jobs and Oracle A1 use the same image digest and CLI. Cloud scheduling is external. Oracle systemd templates and the concrete Cloud Run deployment script are in `deploy/`. No local disk is authoritative. Using PostgreSQL, S3-compatible APIs, OCI images, and two example compute providers improves replaceability but is not a claim of zero vendor lock-in.

## Verification status

The existing filesystem suites have local evidence only when rerun against the current tree. Container, PostgreSQL, MinIO, Cloud Run, Oracle A1, real S3, multi-architecture publication, and forced-termination continuity remain unverified until their CI/tooling/credential gates run. No deployment or multi-architecture success is claimed here.

Free allocations are account, billing, region, and policy dependent and can change. Google's official pricing currently lists a Cloud Run monthly free tier measured in vCPU-seconds and GiB-seconds, and Cloud Scheduler pricing lists three jobs per billing account at no charge. Oracle documents Always Free Ampere A1 compute as up to 3,000 OCPU-hours and 18,000 GB-hours per month in the home region. Verify current eligibility before deployment; these facts are not a guarantee of capacity or a no-cost bill.
